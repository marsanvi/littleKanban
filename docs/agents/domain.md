# Domain Docs

## Before exploring

Read `GLOSSARY.md` at the repository root and any relevant ADRs in `docs/adr/`. If either is absent, proceed; `/domain-modeling` creates them when terms or decisions are resolved.

## Layout

This is a single-context repository: use one root `GLOSSARY.md` and `docs/adr/` for architecture decision records.

## Vocabulary and decisions

Use glossary terms consistently in issues, proposals, hypotheses, and tests. If a concept is missing, reconsider the terminology or note the gap for `/domain-modeling`. Surface conflicts with existing ADRs explicitly rather than silently overriding them.
